# 当前安全修复与原 Web UI 行为边界

本文件取代本轮曾提出的首次唯一口令、业务 HTTPS、额外 CA 确认、独立安全时钟及发布材料登记流程。历史审查和测试记录保留在 audit 中，不代表当前产品策略。

- 以已提交的 0.6.4 为行为基线。保留原通用初始口令、HTTP 80、直接 IP 和原映射域名／端口访问；不新增首次配置页面或串口临时口令。
- admin 保留原安全、配置、网络、文件及升级页能力，包括可导出密钥的导出、SD／SPIFFS／WWW 文件和 SFTP 操作。不可导出标记继续有效；账号管理和原终端／指令／自动化专属操作继续按原 Root 权限执行。
- API 在实际入口检查登录身份、声明的权限及请求方法；匿名业务写入和用 JSON 自报身份仍被拒绝。原 Web UI 在现有调用处声明读写方法，不增加一份运行时接口映射。
- 浏览器仍拒绝不同 Origin 及重复请求头；撤销“Host 必须是本机”的白名单。允许映射 Host 意味着不再宣称完整阻止 DNS rebinding。
- 恢复原 www 分区与 /www 挂载、原固件／WWW 文件、升级及 SD 恢复流程。没有新增发布签名、专用发行密钥或材料登记门槛；保留 API 鉴权、请求长度／时间／容量检查以及 SDK 镜像校验。失败上传不删除先前恢复材料；部分完成必须如实返回。
- 保留既有独立 mTLS 服务；使用原系统／NTP 时间与已安装 CA，不要求新增的逐次 Root 校时确认或 CA 再确认。Device 证书保留原 Viewer 读取与身份查询，不具有 Operator／Admin 管理权限。
- 普通配置包保留原 Developer 证书用途和开机离线读取，仍验证既有固定 CA、签名、接收方与 GCM；不会把离线读取伪装成已确认当前时间。可执行自动化包继续使用严格代码签名用途、当前时间或精确已接受记录。
- 内网及外网暴露方式由设备所有者决定。本轮不启用 eFuse、Secure Boot 或 Flash Encryption，不把这些部署策略记为已修复的漏洞。

源码本地验证、真实浏览器夹具、已刷设备的验证分别记录。后续源码未再次刷入前，不能把旧设备证据称为该源码的真机验收。

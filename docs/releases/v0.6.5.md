# TianshanOS v0.6.5 更新说明（发布候选）

本版本基于 v0.6.4，集中修正 API 的登录鉴权、权限检查、请求边界、日志敏感内容和会话生命周期问题；同时保留现有 Web UI、HTTP 访问方式、初始口令、管理员操作范围、原升级包与 SD 恢复流程，不引入新的部署要求。

## 主要变化

- 补齐 API 与 WebSocket 入口的鉴权、请求方法和参数检查，改密后撤销相关会话，限制日志中的敏感内容。
- 修正文件读写、上传完整性、执行结果与取消操作的生命周期；保留原文件管理、指令及自动化的合法操作。
- 修正专用固件上传入口错误返回 409，以及已验证的 DNS、HTTP 读取和数据源相关处理。
- 修正 AGX 复位状态更新，收敛控制器非冷启动时的 LPMU 自动电源脉冲，保留手动控制及原冷启动检测。
- 优化指令页未选择主机时的排版，以及窄屏顶栏间距，保留已选择主机后的操作流程。
- 更新发布仓库识别与 CI 所需 SDK 文件，保留原固件、网页和串口升级包格式。

## 升级方式与数据保留

请先确认设备当前版本及分区布局，并备份配置。固件与 WWW 网页必须使用同一 Release 的配套文件。

| 当前版本／布局 | 升级方式 |
|---|---|
| 0.6.0、0.6.1、0.6.2，以及更早的旧分区布局 | **必须使用本 Release 的 USB／串口升级 ZIP 包**，按包内 README 操作；不能只在 Web UI 上传固件或执行 OTA。 |
| 0.6.3、0.6.4，且已正确采用 0.6.3 新分区布局 | 可通过现有 **Web UI 升级**，更新配套固件和 WWW；本次 0.6.5 没有新增分区调整。 |
| 版本来源不明、定制固件，或不能确认布局 | 不要仅凭版本号判断。请先联系厂商核对；配套串口工具会检查实际布局，不匹配时停止。 |

串口升级要求来自 **0.6.3 的存储分区调整**，不是本次 API 修复新增的限制。USB／串口升级不等于全片擦除。

### 配置、密钥和 SD 卡怎么保留

- **配置**：升级前导出可导出的配置，并备份 SD 卡配置文件。旧布局首次升级只初始化原来未分配的新增系统／自动化配置区域；保留原 SD 卡并插好，首次启动会尝试迁移旧配置。保留文件不代表所有旧配置已成功迁移，升级后须逐项核对网络、风扇、主机、指令和自动化，必要时从备份恢复或重新配置。已使用新布局的设备，配套串口工具重复升级时保留系统配置区和自动化应急副本。
- **密钥与证书**：配套串口工具不擦除原密钥区域及 NVS 加密材料，也不要求删除或更换现有证书。正式升级包不会携带测试身份；升级后请核对原证书、SSH 主机认证及需要解密的配置能否正常使用。密钥备份或导出仍受原有可导出标记限制，不应假定全部私钥都能导出。
- **SD 卡数据**：配套工具不格式化或清空 SD 卡；仍建议升级前复制整卡备份，升级时保留原卡，不拔卡、不删除旧配置。卡内的旧恢复固件／恢复清单也会被保留，请在升级前按包内说明检查，避免首次启动触发非预期的旧版恢复。

请勿使用全片擦除、旧分区表或旧版密码恢复镜像代替本次升级。首次串口迁移会更新两个应用槽，不能依赖另一槽自动退回旧布局版本。升级期间保持供电，完成后再检查业务功能。

### 回退注意

密码恢复专用镜像会重置账户，不是日常升级或保留身份的回滚镜像。曾运行实验性密码格式的设备，回退旧固件前还需确认账户已迁回原格式；跨分区布局回退应由厂商核对，不能只刷旧应用或旧分区表。

## 已知问题

控制器在维护重启后曾出现网页/API 持续无法访问；最后两轮取证未复现，根因仍未确定，本版本不宣称解决该问题。HTTP 客户端异步使用的 SDK 合同差异也保留为未决风险，尚未证明它是上述失联原因。

指令页无可选主机或主机列表加载失败时的引导仍可能指向不存在的主机卡片，原创建检查仍生效。
